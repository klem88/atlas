# Les progressions du jazz : plan d'implémentation

> **Pour les agents :** sous-skill requis, superpowers:executing-plans (exécution dans cette session). Les étapes sont des cases à cocher.

**But :** un exercice au piano qui montre, pour 11 progressions du jazz transposables dans les 12 tonalités, quel mode jouer sur chaque accord. La page joue un accompagnement swing, propose six paliers rythmiques et tient un carnet de tempos tamponnés.

**Architecture :**
- Calculs purs et testés : dans `viz/jazz-ii-v/domain/` (grilles, orthographe, modes, voicings, paliers) et dans le socle (`swing.ts`, `logbook.ts`).
- Audio : une horloge Web Audio (`band.ts`) qui ordonnance par lots des événements calculés à l'avance. La basse et la main gauche passent par la note de piano exportée de `piano.ts`, la batterie par `drums.ts`.
- Données : un pipeline compte les progressions dans l'iRb et écrit deux fichiers JSON statiques.

**Stack :** Vite, TypeScript strict, Vitest, Web Audio, sans framework.

**Spec :** [docs/chantiers/jazz-ii-v.md](../../chantiers/jazz-ii-v.md)

## Contraintes globales

- Langue : français pour l'interface, les commentaires et les commits. Tutoiement dans l'interface. Apostrophe typographique ’ dans les textes affichés.
- Noms d'accords à la française : « Ré m7 », « Sol 7 », « Do 7M », « Si ø », « Mi 7alt », « La m6 », « Do♯ °7 ».
- Chemins publics : uniquement via `assetUrl()`.
- `npm test` et `npm run typecheck` au vert avant chaque commit. Un commit par tâche, avec la fiche mise à jour.
- Design : jetons de `tokens.css`, un seul accent, clair, sombre et mobile 375 px.
- Stockage : `localStorage`, chaque lecture et écriture dans un try/catch.

## Tâche 1 : orthographe et grilles

Interfaces produites :

```ts
// spelling.ts
export type Mode = 'majeur' | 'mineur';
export const CYCLE_QUARTES: readonly number[]; // [0,5,10,3,8,1,6,11,4,9,2,7]
export function tonicName(pc: number, mode: Mode): string;           // 1,'majeur' → 'Ré♭' ; 1,'mineur' → 'Do♯'
export function spellDegree(tonic: string, degree: string): string; // ('Do','b2') → 'Ré♭' ; ('Do','#1') → 'Do♯'
// progressions.ts
export type Qualite = 'm7' | '7' | '7M' | '6' | 'ø' | '7alt' | 'm6' | '°7';
export interface AccordGrille { degre: string; qualite: Qualite; temps: number; chiffrage: string; mode: ModeId }
export interface Progression { id: string; titre: string; court: string; mode: Mode; accords: AccordGrille[]; ou: string; motifs: Motif[][] }
export interface Motif { intervalle: number; qualites: Quality[] } // intervalle depuis le 1er accord ; Quality de chords.ts
export const PROGRESSIONS: readonly Progression[];
export interface AccordJoue extends AccordGrille { racine: number; nom: string; debut: number } // debut en temps
export function transpose(p: Progression, tonique: number): AccordJoue[];
```

Tests :
- ii–V–I en Do donne « Ré m7, Sol 7, Do 7M ».
- La substitution tritonique en Do donne « Ré♭ 7 », et le diminué de passage « Do♯ °7 ».
- Le backdoor en Mi♭ donne « La♭ m7, Ré♭ 7 ».
- Aucun nom ne contient de double altération, dans aucune tonalité.
- Chaque grille fait un nombre entier de mesures de 4 temps.

## Tâche 2 : modes et voicings

```ts
export type ModeId = 'ionien'|'dorien'|'mixolydien'|'lydien'|'locrien'|'altere'|'phrygienDominant'|'melodique'|'lydienB7'|'tonDemiTon';
export const MODES: Record<ModeId, { nom: string; intervalles: number[] }>;
export function notesDuMode(racine: number, mode: ModeId): number[];  // classes de hauteur
export function notesGuides(racine: number, q: Qualite): [number, number]; // 3ce, 7e (pour °7 : ♭3, 𝄫7)
export function voicingsMainGauche(accords: AccordJoue[], kind: 'guides' | 'sansFondamentale'): number[][]; // MIDI
```

Tests :
- Le dorien de ré contient fa et si.
- Le locrien de si contient do.
- Les notes guides de Ré m7 sont fa et do.
- Dans un ii–V–I, la 7e de chaque accord descend d'un demi-ton sur la 3ce du suivant (do→si, fa→mi).
- Toutes les notes de la main gauche restent dans [50, 64].
- Chaque voicing contient la 3ce et la 7e de son accord.
- Le mouvement total d'un ii–V–I est inférieur ou égal à 4 demi-tons par accord.

## Tâche 3 : swing.ts (socle)

```ts
export interface Hit { beat: number; kind: 'basse' | 'ride' | 'charleston' | 'piano'; midi?: number; dur: number; vel: number }
export interface ChordSpan { root: number; start: number; beats: number; tones: number[] } // tones : classes de hauteur
export function walkingBass(chords: ChordSpan[], loopBeats: number): Hit[];
export function drumPattern(loopBeats: number): Hit[];
export function swingFraction(bpm: number): number;  // 2/3 jusqu'à 160, puis décroît jusqu'à 0,58 à 260
export function swungBeat(beat: number, frac: number): number; // n,5 → n + frac
```

Tests :
- Le temps 1 de chaque accord joue sa fondamentale.
- Le dernier temps avant un changement d'accord est à un demi-ton de la fondamentale suivante.
- La basse reste dans [36, 55], avec une note par temps.
- La ride tombe sur 1, 2, 2&, 3, 4, 4& ; le charleston sur 2 et 4.
- `swungBeat(1.5, 2/3)` vaut 1,6667.

## Tâche 4 : paliers

```ts
export interface Palier { n: 1|2|3|4|5|6; titre: string; consigne: string[]; rythme: string /* notation texte */; exemple(accords: AccordJoue[]): Hit[] }
export const PALIERS: readonly Palier[];
```

Tests :
- Palier 1 : une frappe de deux notes par accord, au début de l'accord.
- Palier 2 : un accord de 4 temps est frappé à 0 et à 1,5.
- Palier 3 : chaque accord est frappé à son début moins 0,5 (sur le 4& précédent), modulo la boucle.
- Paliers 4 à 6 : leur exemple de main gauche est celui du palier 2.


## Tâche 6 : motifs et pipeline iRb

`trouverMotif(suite: Chord[], motif: Motif[]): number[]` (indices de départ). La suite est aplatie, les répétitions fusionnées, et les trois premiers accords sont recopiés à la fin pour le retour au début du morceau.

Tests :
- Dm7 G7 Cmaj7 est trouvé en position 0.
- Le motif est trouvé quelle que soit la tonalité.
- Un accord majeur ne correspond pas à un motif qui attend un m7.

Le pipeline écrit deux fichiers :
- `frequences.json` : `{ total, progressions: { id, n, morceaux: [indice, débuts[]][] }[] }`
- `standards.json` : `{ morceaux: { t, c?, a?, ton, accords: string[] }[] }`

et le `REPORT.md`.

## Tâche 7 : audio (piano exporté, batterie, horloge)

`band.ts` expose :

```ts
new Band()
.play(loop: { hits: Hit[]; beats: number }, bpm)
.setLoop(...)
.setTempo(bpm)
.stop()
.position(): { beat: number } | null
.playing: boolean
```

Comportement :
- un décompte de 4 temps au charleston ;
- l'ordonnancement se fait par avance de 0,15 s, avec un minuteur de 25 ms ;
- au changement de tempo, l'horloge se recale sur le temps en cours.
